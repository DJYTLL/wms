# 前端页面性能与防卡顿开发规范

适用范围：

- ERP 列表页、单据页、系统管理页等所有需要通过菜单打开的前端页面。
- 尤其适用于包含表格、列设置、汇总栏、搜索区、操作列、弹窗、打印预览、远程下拉、权限列控制的页面。

目标：

- 菜单点击后页面外壳必须快速出现。
- 首屏只渲染用户立刻能看到和理解的内容。
- 表格 body、列设置、汇总栏、操作列、弹窗、打印预览等重内容必须延后。
- 性能问题必须用埋点定位，不允许凭感觉猜。

## 1. 核心原则

### 1.1 页面打开分两阶段

任何新页面都必须区分：

| 阶段       | 内容                                | 要求               |
| -------- | --------------------------------- | ---------------- |
| 首屏 shell | 标题、搜索区外壳、操作区、表格卡片外壳、轻量占位          | 菜单点击后立即渲染        |
| 延后内容     | 表格 body、列设置、汇总栏、操作列、弹窗、打印预览、复杂选择器 | 页面 mounted 后异步挂载 |

不要让首屏等待：

- 列权限接口。
- 用户表格设置接口。
- 大表格组件初始化。
- 打印组件加载。
- 复杂弹窗组件加载。
- 下拉基础数据加载。
- 首次列表接口返回。

### 1.2 首屏不能直接挂重组件

列表页入口组件禁止直接引入以下内容：

```ts
import ErpDataTable from '@/components/ErpDataTable.vue';
import PrintPreviewDialog from '@/components/PrintPreviewDialog.vue';
```

正确做法：

- 入口页只保留页面标题、筛选区、操作按钮、占位卡片。
- 表格和重弹窗放到 `DeferredPanel` 组件中。
- `DeferredPanel` 通过异步 loader 延后加载。

### 1.3 数据不能阻塞页面进入

菜单点击后应先进入页面，再异步取数据。

错误做法：

```ts
onMounted(async () => {
  await fetchList();
  await fetchColumns();
  await fetchUserSettings();
  showTable.value = true;
});
```

正确做法：

```ts
onMounted(() => {
  scheduleDeferredPanelMount();
  void fetchList();
  void fetchLightBaseData();
});
```

## 2. 推荐页面结构

### 2.1 入口页只负责首屏

入口页职责：

- 页面标题。
- 搜索区外壳。
- 固定操作按钮。
- 表格卡片占位。
- 发起列表数据请求。
- 发起延后 panel 挂载。
- 发起同组页面预热。

入口页不应该负责：

- 表格 body。
- 操作列按钮模板。
- 汇总栏。
- 打印弹窗。
- 商品历史弹窗。
- 复杂编辑弹窗。
- 表格列设置弹窗。

### 2.2 重内容放入 DeferredPanel

示例结构：

```text
ErpXxxDraftManagement.vue
ErpXxxApprovedManagement.vue
XxxDraftDeferredPanel.vue
XxxApprovedDeferredPanel.vue
xxxDeferredPanelLoaders.ts
xxxWarmupCache.ts
```

其中：

- `Management.vue` 是轻入口。
- `DeferredPanel.vue` 是真实表格和弹窗。
- `Loaders.ts` 统一缓存异步组件 promise。
- `WarmupCache.ts` 统一缓存列表首屏数据。

## 3. 异步组件加载规范

### 3.1 不要在性能敏感入口中直接使用 defineAsyncComponent 包重 panel

当菜单点击要求“立即响应”时，入口页不要这样写：

```ts
const DeferredPanel = defineAsyncComponent(loadDeferredPanel);
```

原因：

- 即使 chunk 已经预热完成，`defineAsyncComponent` 仍可能产生额外异步调度。
- 埋点会表现为 loader 已经 `cache-hit:resolved`，但 panel `setup` 仍滞后。

### 3.2 使用已解析组件 ref 挂载

推荐写法：

```ts
import type { Component } from 'vue';
import { markRaw, ref, shallowRef } from 'vue';
import { loadXxxDeferredPanel } from './xxxDeferredPanelLoaders';

const DeferredPanel = shallowRef<Component | null>(null);
const shouldMountDeferredPanel = ref(false);

const scheduleDeferredPanelMount = () => {
  markPerf('page:deferred-panel-request');
  if (shouldMountDeferredPanel.value) return;

  loadXxxDeferredPanel().then((module) => {
    DeferredPanel.value = markRaw(module.default);
    shouldMountDeferredPanel.value = true;
  }).catch((error) => {
    notifyError(error);
  });
};
```

模板：

```vue
<component
  v-if="shouldMountDeferredPanel && DeferredPanel"
  :is="DeferredPanel"
  :rows="tableData"
  :loading="loading"
/>
<div v-else class="table-card">
  <div class="table-placeholder"></div>
</div>
```

### 3.3 loader 必须缓存 promise

同一个 deferred panel loader 必须被路由预热和页面挂载复用。

推荐写法：

```ts
const createCachedDeferredPanelLoader = <T>(load: () => Promise<T>) => {
  let cachedPromise: Promise<T> | null = null;

  return () => {
    if (cachedPromise) return cachedPromise;
    cachedPromise = load().catch((error) => {
      cachedPromise = null;
      throw error;
    });
    return cachedPromise;
  };
};
```

必须避免：

- 路由预热用一个 `import()`。
- 页面挂载又写另一个 `import()`。
- 每次点击都重新创建 loader promise。

## 4. 数据预热与缓存规范

### 4.1 同组页面应提前预热

如果业务天然成组，例如：

- 销售单草稿。
- 销售单已审核。
- 销售退货草稿。
- 销售退货已审核。

进入任意一个页面后，应预热同组页面：

- 页面入口 chunk。
- deferred panel chunk。
- 默认第一页列表数据。

### 4.2 首屏列表数据缓存

列表默认查询应使用短期内存缓存。

缓存 key 必须包含：

- url。
- page。
- size。
- status。
- keyword。
- customerId / supplierId。
- dateRange。
- 其他会影响结果的筛选条件。

缓存失效时机：

- 新增。
- 编辑保存。
- 审核。
- 删除。
- 红冲。
- 退货。
- 导入。
- 影响列表结果的基础数据变更。

### 4.3 基础数据延后加载

客户、供应商、仓库、商品等基础数据不要阻塞首屏。

要求：

- 搜索下拉可以先显示空选项或 loading。
- 页面外壳和表格占位必须先出现。
- 基础数据请求完成后再补齐选项文本。

## 5. 埋点规范

### 5.1 必须埋的导航性能点

菜单点击到页面可用至少需要以下埋点：

```text
menu:click
router:beforeEach
router:beforeEach:next
router:afterEach
page:setup
page:mounted
page:list-fetch-start
page:list-cache:hit/miss
page:list-fetch-end
page:deferred-panel-request
page:deferred-panel-loader:request
page:deferred-panel-loader:cache-hit:pending
page:deferred-panel-loader:cache-hit:resolved
page:deferred-panel-loader:start
page:deferred-panel-loader:resolved
page:deferred-panel-setup
page:deferred-panel-mounted
request:start
request:finish
```

### 5.2 日志判断规则

| 现象                                                     | 说明                       | 处理方向                         |
| ------------------------------------------------------ | ------------------------ | ---------------------------- |
| `router:afterEach` 慢                                   | 路由解析或前一个页面卸载慢            | 查路由组件、keep-alive、前页卸载副作用     |
| `page:setup` 慢                                         | 入口页同步代码太重                | 拆入口页逻辑，移出重 computed、重 import |
| `list-cache:miss` 后接口慢                                 | 后端或网络慢                   | 做接口优化、缓存、分页、索引               |
| `list-cache:hit` 但首屏慢                                  | 前端渲染或同步计算慢               | 查表格、列设置、watch、computed       |
| `loader:cache-hit:resolved` 但 `deferred-panel-setup` 慢 | chunk 已加载，组件 setup 慢     | 拆 deferred panel 内部组件        |
| `deferred-panel-mounted` 慢                             | DOM 渲染或 Element Plus 表格重 | 虚拟滚动、减少列、延后操作列               |

### 5.3 不允许只看接口耗时

接口 30ms 不代表页面不卡。

必须同时看：

- 菜单点击到 `router:afterEach`。
- 菜单点击到入口页 `mounted`。
- 菜单点击到列表数据 ready。
- 菜单点击到 deferred panel mounted。
- deferred panel setup 是否存在 300ms 以上同步阻塞。

## 6. 表格页拆分清单

新增或重构表格页时，至少检查以下内容是否需要拆分：

- 表格 body。
- 汇总栏。
- 列设置。
- 操作列。
- 打印弹窗。
- 导入弹窗。
- 商品选择弹窗。
- 历史记录弹窗。
- 审核确认弹窗。
- 红冲/作废弹窗。
- 大型搜索下拉。
- 远程商品搜索。
- 行内编辑组件。
- 权限列计算。
- 表格列宽拖拽逻辑。
- 大量 formatter。
- 页面级快捷键监听。

规则：

- 首屏不需要立刻交互的，都延后。
- 首屏只需要外观稳定的，用占位或 skeleton。
- 用户点击后才需要的，用 `defineAsyncComponent` 或动态 import 放到 panel 内部。

## 7. 搜索区与操作区性能要求

搜索区不能因为性能优化牺牲布局稳定性。

要求：

- 操作按钮固定在搜索卡片第一行右侧。
- 筛选控件整体换行，不允许遮挡按钮。
- `el-select`、远程选择器、日期范围必须有明确宽度或最小宽度。
- 不允许把复杂远程选择器作为首屏同步重组件。

如果搜索控件较重：

- 首屏先渲染轻量外壳。
- 选项数据异步加载。
- 远程搜索逻辑在用户输入后再触发。

## 8. 回归测试要求

### 8.1 结构测试

每个性能敏感页面必须有测试锁住：

- 入口页不直接引入重表格。
- 入口页不直接引入打印弹窗。
- 入口页使用轻 shell。
- deferred panel 内才出现真实表格。
- deferred panel loader 被路由预热和页面挂载复用。

### 8.2 性能行为测试

至少测试：

- 菜单点击会预取重 chunk。
- 页面刷新不清空已有行，避免闪白。
- 默认列表请求命中缓存时不重复发起网络请求。
- 入口页 mounted 不等待 deferred panel。

### 8.3 类型和构建检查

提交前必须跑：

```bash
npm run type-check
npm run build-only
```

如改动了相关测试，必须跑对应 `node xxx.test.mjs`。

## 9. 开发前检查清单

开发新前端页面前，先回答：

- 这个页面首屏只需要展示哪些内容？
- 哪些组件可以延后到 mounted 后？
- 哪些组件只有用户点击后才需要？
- 哪些接口不能阻塞页面进入？
- 是否有同组页面可以预热？
- 是否需要列表默认数据缓存？
- 是否已有导航性能埋点？
- 是否能从日志区分接口慢、chunk 慢、setup 慢、DOM 渲染慢？
- 是否有测试锁住入口页不直接引入重组件？

没有回答清楚前，不要开始堆页面代码。

## 10. 常见反模式

禁止以下写法：

- 一个页面文件同时包含搜索区、表格、弹窗、打印、导入、行内编辑、所有业务动作。
- 页面 mounted 前等待多个接口全部返回。
- 列设置、列权限、用户表格设置阻塞首屏。
- 首屏直接挂载完整 `ErpDataTable`。
- 打印弹窗直接进入入口 chunk。
- 每次菜单点击重新加载同一个 deferred panel chunk。
- 没有埋点就讨论“感觉哪里慢”。
- 只优化接口，不看组件 setup 和 mounted。
- 为了不卡直接隐藏功能，但没有补异步挂载和测试。

## 11. 推荐验收标准

一次页面性能优化是否合格，看以下标准：

- `router:afterEach` 通常在几十毫秒内完成。
- 入口页 `setup + mounted` 不依赖列表接口返回。
- 默认列表缓存命中时，`list-fetch-end` 应接近立即完成。
- deferred panel loader 预热后应出现 `cache-hit:resolved`。
- 如果 `cache-hit:resolved` 后仍慢，继续拆 panel 内部，而不是继续加接口缓存。
- 用户快速切换同组页面时，不应出现明显白屏或整页卡死。

## 12. 销售单优化经验固化

本次销售单页面优化得到的关键结论：

- 销售草稿、销售已审核、销售退货草稿、销售退货已审核必须拆成独立入口页。
- 表格 body、汇总栏、列设置、操作列、打印弹窗必须放入 deferred panel。
- 列表默认数据和 deferred panel chunk 要提前预热。
- 当日志显示 `loader:cache-hit:resolved` 后 `deferred-panel-setup` 仍慢，问题已经不是网络或 chunk 加载，而是 Vue 组件 setup 或表格渲染。
- 对性能敏感入口，优先使用“已解析组件 ref + `<component :is>`”挂载重 panel，避免 `defineAsyncComponent` 额外调度影响体感。
- 优化必须以埋点为准，每轮改动后让日志证明瓶颈是否移动。
