# 销售退货单切换标签数据丢失复盘

## 问题现象

新增销售退货单时，用户在页面中填写客户、退货来源、明细行、仓库库位、数量、价格、备注等内容后，切换到其他标签页，再切回新增销售退货单，已填写但未保存的数据会被清空。

典型路径：

- `/erp/sale-returns/draft/create`
- 从新增销售退货单切到销售退货列表、其他销售退货详情，或系统顶部多标签中的其他页面
- 再切回新增销售退货单，表单回到初始化状态

## 根因

前端主布局 `src/layouts/MainLayout.vue` 使用 `<keep-alive>` 缓存路由组件，理论上切换标签时表单实例应该保留。

真正导致清空的是销售退货表单自身的路由监听：

```ts
watch(
  () => route.fullPath,
  (newPath) => {
    if (newPath === lastRouteKey.value) return;
    if (!isPageActive.value) return;
    lastRouteKey.value = newPath;
    pagePath.value = route.path;
    if (!isSaleReturnRoute.value) return;
    loadDetail();
  }
);
```

这个监听会在离开当前标签页时触发。因为当前组件实例仍处于 keep-alive 生命周期中，路由从新增页切到其他页面的瞬间，监听先执行了 `loadDetail()`。

`loadDetail()` 在新增页里会先执行 `resetForm()`，然后初始化单号、单据时间和空明细行：

```ts
const loadDetail = async () => {
  if (!isSaleReturnRoute.value) return;
  isInitializing.value = true;
  resetForm();
  if (!isEditing.value) {
    await fetchNextOrderNo();
    formData.orderAt = formatDateTime(new Date());
    formData.status = 'DRAFT';
    addItem();
    applyDefaultMethods();
    isInitializing.value = false;
    return;
  }
  // 编辑页加载详情...
};
```

所以问题不是 keep-alive 没生效，而是表单在切出时主动重新加载并重置了自己。

## 处理方式

在 `src/views/erp/ErpSaleReturnForm.vue` 的 `route.fullPath` 监听中增加当前实例路径校验：

```ts
watch(
  () => route.fullPath,
  (newPath) => {
    if (newPath === lastRouteKey.value) return;
    if (!isPageActive.value) return;
    if (route.path !== pagePath.value) return;
    lastRouteKey.value = newPath;
    if (!isSaleReturnRoute.value) return;
    loadDetail();
  }
);
```

关键点：

- `pagePath` 记录当前表单实例创建时对应的页面路径。
- 当用户切换到其他标签页时，`route.path` 已经变成新页面路径，不再等于当前实例的 `pagePath`。
- 这种情况下直接 `return`，避免当前新增页实例执行 `loadDetail()` 和 `resetForm()`。
- 当前页内部确实需要根据同一路径的 query 或状态变化刷新时，仍可继续执行后续逻辑。

## 排查同类问题的提示

遇到“切换标签页后表单数据丢失”时，不要只检查 `<keep-alive>` 是否存在，还要检查页面组件内部是否在这些时机重置表单：

- `watch(() => route.path)`、`watch(() => route.fullPath)`、`watch(() => route.params.id)`
- `onActivated()`
- `onDeactivated()`
- `onBeforeUnmount()`
- 自定义标签关闭事件，例如 `tags:closing`、`tags:close`

重点查找这些函数调用：

- `loadDetail()`
- `resetForm()`
- `initForm()`
- `fetchDetail()`
- `createEmptyItem()`
- 任何会覆盖 `formData` 或 `formData.items` 的逻辑

