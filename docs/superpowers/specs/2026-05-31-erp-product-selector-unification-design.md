# ERP 商品选择框统一为销售单模式设计

**目标**

将 ERP 中“可编辑业务录单/弹窗里真正用于选商品的输入控件”统一为销售单当前使用的商品选择模式，提升跨页面的一致性，减少静态下拉导致的搜索、回填和已选值丢失问题。

**范围**

本次仅覆盖以下页面中可编辑的商品选择输入控件：

- `D:/project/auto-parts-wms-vue/src/views/erp/ErpPurchaseOrderForm.vue`
- `D:/project/auto-parts-wms-vue/src/views/erp/ErpSaleReturnForm.vue`
- `D:/project/auto-parts-wms-vue/src/views/erp/ErpPurchaseReturnForm.vue`
- `D:/project/auto-parts-wms-vue/src/views/erp/ErpAssemblyOrderForm.vue`
- `D:/project/auto-parts-wms-vue/src/views/erp/ErpDisassembleOrderForm.vue`
- `D:/project/auto-parts-wms-vue/src/views/erp/ErpStockTransferManagement.vue`
- `D:/project/auto-parts-wms-vue/src/views/erp/ErpStockCountManagement.vue`

明确不在本次范围内：

- 列表筛选区中的商品下拉
- 打印页、预览页、只读展示页
- 与商品无关的客户、供应商、仓库、库位选择器

**基准实现**

以 `D:/project/auto-parts-wms-vue/src/views/erp/ErpSaleOrderForm.vue` 的商品选择模式作为基准，统一以下能力：

- `el-select` 使用 `filterable + remote + reserve-keyword`
- 通过远程接口按关键字搜索商品
- 下拉候选变化时，当前已选商品仍能保留并正常展示
- 首次展开或需要时可触发默认搜索，避免空下拉影响录单
- 候选项生成与已选值兜底逻辑统一，避免各页重复维护

**按业务保留的差异**

销售/退货/采购类页面继续保留各自业务前置约束：

- 销售单、销售退货单保留客户上下文约束
- 采购单、采购退货单保留供应商上下文约束

库存作业类页面不引入不适用的交易约束：

- 库存调拨、盘点、组装、拆装页面采用远程搜索和已选值兜底
- 不增加客户/供应商未选择时禁用商品选择的规则

内联编辑按钮采取保守策略：

- 适合直接维护商品主数据的交易单据页可以保留或补齐
- 库存作业页默认不新增商品内联编辑按钮，避免在作业场景引入过重操作

**实现方式**

优先抽取可复用的商品搜索与候选合并逻辑，而不是逐页复制销售单代码。目标是让各页面共享同一套行为约束，但仍允许页面保留自己的业务参数、禁用规则和选中后联动逻辑。

建议复用的能力包括：

- 远程查询触发与防抖/节流边界
- 搜索结果与当前已选项合并
- 按当前行商品 ID 生成可选项列表
- 首次展开时加载默认候选

页面自身继续负责：

- 商品变更后的价格、库存、库位、组装明细等业务联动
- 客户/供应商/单据来源等上下文依赖
- 页面特有的按钮、提示和布局

**数据流**

1. 用户聚焦商品选择框或输入关键字。
2. 页面通过统一商品搜索逻辑请求商品列表。
3. 搜索结果与当前已选商品合并，生成当前行可选列表。
4. 用户选中商品后，页面继续执行原有的 `handleProductChange` 等业务联动。
5. 页面在加载历史单据、复制单据、编辑草稿时，仍可通过已选值兜底逻辑显示旧商品。

**错误处理**

- 远程搜索失败时不清空当前已选商品
- 搜索失败后停止 loading，允许用户继续输入重试
- 当前商品已被停用但已存在于单据中时，仍应允许回显并展示当前值

**测试策略**

先补失败测试，再改实现。重点锁定以下行为：

- 目标页面的可编辑商品输入控件使用统一远程搜索模式，而不是本地静态下拉
- 当前已选商品不会因搜索结果变化而消失
- 交易单据页保留原有客户/供应商约束
- 库存作业页不会被错误加上客户/供应商约束

测试以页面级前端测试为主，必要时补充公共工具单测。

**风险与兼容性**

- 当前仓库已有未提交修改，改造时必须避免覆盖用户现有变更
- 多个页面可能已经各自演化出局部差异，统一时要优先保留业务联动，避免只追求“长得一样”
- 如果个别页面的商品来源并非通用商品搜索接口，需要在实现前单独确认，而不是强行套用
