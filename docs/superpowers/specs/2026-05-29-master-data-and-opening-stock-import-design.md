# 基础资料与期初库存 Excel 导入设计

日期：2026-05-29

## 背景

当前仓库中，供应商导入已有一套“粘贴 Markdown 表格”的历史实现，但不支持直接上传 Excel；客户、配件、库存期初也缺少与业务现有 Excel 模板对齐的标准导入能力。

业务当前提供了 4 份迁移模板：

1. `C:/Users/Administrator/Downloads/供应商档案表.xls`
2. `C:/Users/Administrator/Downloads/客户档案表.xls`
3. `C:/Users/Administrator/Downloads/配件档案列表.xls`
4. `C:/Users/Administrator/Downloads/库存明细浏览表.xls`

本次目标是围绕这 4 份模板，建立一套统一风格的 Excel 导入能力，覆盖：

1. 供应商主数据导入
2. 客户主数据导入
3. 配件主数据导入
4. 库存期初导入

其中库存导入并不是商品建档的替代，而是用于将历史库存快照导入本地系统，作为库存基线。

## 目标

1. 供应商、客户、配件都支持直接上传 `.xls` / `.xlsx` 导入。
2. 库存明细浏览表支持导入为“期初库存/库存余额基线”。
3. 导入入口按业务归属分布在对应页面，不做一个杂糅的万能导入入口。
4. 导入结果支持成功、失败、警告、建议和批次追溯。
5. 库存导入与商品主数据导入严格分层，避免库存表反向污染商品档案。

## 非目标

1. 不建设单独的“迁移中心”大页面。
2. 不让库存导入自动补建缺失商品。
3. 不让库存导入顺手更新商品主数据。
4. 不在本次设计里承诺将 4 份 Excel 的全部列 100% 全量映射到正式业务字段。

## 统一方案

本次采用“前端上传 Excel，后端解析 Excel，按资源分开执行业务导入”的方案。

### 统一原则

1. 前端上传 `.xls/.xlsx`
2. 后端统一解析第一张工作表
3. 第一行作为表头
4. 按模板标准列名为主，允许有限别名兼容
5. 每类资源走自己的导入业务规则，不使用单一万能导入逻辑
6. 返回统一风格的批次结果与导入明细

## 接口设计

按资源拆分接口，而不是设计一个万能 Excel 导入接口。

### 建议接口

1. `POST /api/erp/suppliers/import`
2. `POST /api/erp/customers/import`
3. `POST /api/erp/products/import`
4. `POST /api/erp/stocks/opening-import`

### 请求格式

统一为：

`Content-Type: multipart/form-data`

字段：

1. `file`
   - 必填
   - 支持 `.xls`、`.xlsx`
2. `sourceName`
   - 选填
   - 默认使用上传文件名

### 返回格式

统一风格返回：

1. `batchId`
2. `batchNo`
3. `totalCount`
4. `successCount`
5. `failedCount`
6. `items`

明细项统一保留：

1. 状态
2. 错误字段
3. 错误信息
4. 建议处理
5. 告警信息
6. 匹配策略

## Excel 解析通用规则

1. 仅允许 `.xls` 与 `.xlsx`
2. 默认读取第一张工作表
3. 第一行作为表头
4. 从第二行开始读取数据
5. 全空白行跳过
6. 单元格按显示文本或格式化后的文本读取，避免科学计数法和日期格式混乱
7. 列名先裁剪、归一化，再进入业务层

#### 已确认业务规则

1. 配件不存在：必须先完成“配件档案列表”导入，再导库存；缺商品则失败
2. 仓库不存在：不阻塞库存导入，先继续导入
3. 供应商不存在：允许为空或仅记备注，不阻塞
4. 库存表中与商品重叠的字段：只做一致性校验，不回写商品主数据
5. 商品字段不一致：仅 warning，不阻塞库存导入

## 主数据与库存的边界

这是本次设计的核心边界：

1. 配件档案列表是商品主数据主来源
2. 库存明细浏览表是库存快照来源
3. 库存导入不得反向覆盖商品主数据
4. 库存导入只按 `仓库 + 编码` 落库存事实数据
5. 库存表里携带的商品属性仅用于校验和告警

## 风险与控制

1. 四类模板字段数量差异很大
   - 通过“核心字段 + 推荐字段 + 留痕字段”分层控制范围
2. 库存表与商品表存在字段重叠
   - 通过“库存不回写商品”原则避免脏覆盖
3. `.xls` 与 `.xlsx` 底层格式不同
   - 通过统一 Workbook 解析层处理
4. 批次能力可能要求新增表结构
   - 实现前先检查结构，必要时顺序新增 migration

## 最终决策

本次将围绕 4 份历史 Excel 模板，建立供应商、客户、配件主数据导入，以及库存期初导入能力。主数据导入与库存导入严格分层，库存导入只负责建立本地库存基线，不负责补建商品，也不反向覆盖商品主数据。
