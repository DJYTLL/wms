# ERP 供应商新增弹窗改版设计

## 背景

当前 `ErpSupplierManagement.vue` 中的供应商新增/编辑使用 `700px` 宽的单列 `el-dialog`。

现状问题：

- 字段按技术落库顺序平铺，缺少业务分层。
- 首屏没有重点信息区，用户打开后需要长距离滚动。
- 必填信息、常用信息、低频信息混在一起，录入节奏不清晰。
- 联系方式、往来主体、财务字段之间缺少语义分组，理解成本高。
- 底部操作区随页面滚动，长表单状态下保存动作不稳定。

本次目标不是改业务模型，也不是新增字段，而是在保留现有弹窗模式下，重做供应商新增弹窗的信息架构与视觉层次。

## 目标

1. 保留“弹窗新增”交互，不改成整页或抽屉。
2. 将新增表单改成“分组卡片 + 双列布局 + 可选区折叠”。
3. 让用户首屏先完成最关键录入，再按需补充低频字段。
4. 保持现有接口、字段模型、保存行为兼容，优先做前端交互重构。
5. 风格与当前 ERP 页面体系保持一致，不做脱离项目的全新设计语言。

## 非目标

- 不新增数据库字段。
- 不调整后端保存接口或字段语义。
- 不把新增供应商改造成步骤向导。
- 不改造供应商列表页筛选逻辑。

## 方案比较

评估了三种方案：

### 方案 A：分组卡片 + 双列布局 + 可选区折叠

优点：

- 最符合 ERP 主数据录入习惯。
- 用户可以在一个视野里完成核心信息填写。
- 高频字段和低频字段天然分层，压迫感明显下降。
- 对现有实现改造成本适中，风险可控。

缺点：

- 表单组织比原来复杂，需要补充局部样式和分区结构。

### 方案 B：弹窗内 Tab 分页

优点：

- 可以把字段拆散，首屏更短。

缺点：

- 用户需要切换标签才能确认信息是否填全。
- 保存前不容易感知遗漏项。
- 对这种一次性录入的主数据场景不如单页流畅。

### 方案 C：步骤向导

优点：

- 流程感更强。

缺点：

- 增加点击成本。
- 供应商档案不是强流程型业务，不适合强行拆步。
- 编辑场景也会显得冗余。

## 结论

采用 **方案 A：分组卡片 + 双列布局 + 可选区折叠**。

## 改版原则

### 1. 首屏先录关键识别信息

首屏只承载最影响建档成功率的信息：

- 编码
- 供应商名称
- 简称
- 供应商类型
- 区域
- 状态

这组字段回答的是“这个供应商是谁”。

### 2. 联系信息与业务归属独立成组

- 联系人、电话、手机、微信客服、联系方式原文属于“如何联系到对方”。
- 往来类别、往来主体、采购员、默认结算方式、默认付款方式属于“在我方体系中如何归属和使用”。

这两块语义不同，必须拆开。

### 3. 低频字段默认收起

以下字段改为默认折叠：

- 邮箱
- 开户地址
- 税号
- 开户行
- 银行账号
- 历史创建人
- 历史创建时间
- 备注

它们仍然保留，但不应该干扰首次建档。

### 4. 操作区固定

弹窗底部操作栏固定显示：

- 左侧：`展开全部可选项`
- 右侧：`取消`、`保存供应商`

即使表单滚动到底部以外，用户也能稳定执行保存。

## 页面结构设计

### 弹窗层级

- 弹窗宽度从现有 `700px` 提升到约 `920px` 到 `960px`
- 保持居中 `el-dialog`
- 弹窗头部显示：
  - 标题：`新增供应商`
  - 辅助说明：`基础信息优先，财务与历史信息按需展开`

### 头部提示条

在表单正文上方增加一条轻提示区：

- 左侧：`自动生成编码`
- 右侧：`带 * 为必填`

作用：

- 减少用户对编码字段是否可编辑的困惑
- 明确必填规则

### 正文布局

正文采用双列栅格，每个分区用卡片包裹。

字段宽度规则：

- 普通字段：占半列
- 重要字段：如“供应商名称”可占整行
- 文本域：整行

## 分区设计

### 1. 基础识别

字段：

- 编码
- 供应商名称
- 简称
- 供应商类型
- 区域
- 状态

规则：

- `编码` 保持禁用展示，仍然支持自动生成。
- `供应商名称` 是主输入项，需要视觉优先级最高。
- `状态` 保持启用 / 停用 / 黑名单，但位置前移，不再沉到底部。

原因：

- 用户建档时最先确认的是主体身份与状态，不应把状态藏在最后。

### 2. 联系人与沟通

字段：

- 联系人
- 手机
- 电话
- 微信客服
- 联系方式

规则：

- `联系方式` 保持文本域，承接原始联系方式整串。
- `手机` 和 `电话` 并列展示，方便快速录入。
- 该区聚焦“对外沟通方式”，不混入结算字段。

### 3. 业务归属

字段：

- 往来类别
- 往来主体
- 采购员
- 默认结算方式
- 默认付款方式

规则：

- `往来主体` 保持可搜索下拉。
- 在 `往来主体` 下增加提示文案：
  - `既是客户又是供应商时建议绑定主体`
- `默认结算方式` 与 `默认付款方式` 保持同区，符合使用语义。

### 4. 财务与开票信息（可选）

字段：

- 邮箱
- 开户地址
- 税号
- 开户行
- 银行账号

交互：

- 默认折叠
- 用户展开后再填写

### 5. 历史与备注（可选）

字段：

- 历史创建人
- 历史创建时间
- 备注

交互：

- 默认折叠
- `历史创建时间` 保持只读

## 交互规则

### 打开新增弹窗

打开新增弹窗后：

1. 自动获取下一编码
2. 聚焦到“供应商名称”
3. 默认展开：
   - 基础识别
   - 联系人与沟通
   - 业务归属
4. 默认收起：
   - 财务与开票信息
   - 历史与备注

### 打开编辑弹窗

编辑弹窗沿用同一布局，但标题改为 `编辑供应商`。

编辑场景不改变原字段值映射，只改变表现结构。

### 展开全部可选项

点击 `展开全部可选项` 后：

- 展开全部折叠区
- 按钮文案切换为 `收起可选项`

该按钮只控制可选分区，不影响基础区。

### 保存

保存按钮固定在底部右侧，文案统一为：

- 新增：`保存供应商`
- 编辑：`保存修改`

## 校验与提示

本轮不引入新校验规则，但建议按以下优先级组织校验反馈：

- `供应商名称` 缺失优先提示
- 编码自动生成异常时在编码区域内提示
- 往来主体为空时不阻塞保存，但保留辅助文案引导

## 视觉与样式要求

- 保持当前项目白底卡片、浅灰描边、圆角中等的 ERP 风格
- 分区标题要比字段标签更醒目，但不要过重
- 卡片之间留明确间距，避免再次形成“大白板式长表单”
- 表单内边距优先控制在紧凑但可读的范围，不做宽松营销风格
- 弹窗正文允许内部滚动，底部操作栏固定

## 实现建议

前端实现建议：

1. 保留现有 `showModal`、`formData`、`saveData`、`openAddModal`、`openEditModal` 逻辑。
2. 只重构弹窗模板结构与局部样式，不先改接口。
3. 为弹窗新增局部 class，例如：
   - `supplier-dialog`
   - `supplier-dialog__intro`
   - `supplier-section`
   - `supplier-section__grid`
   - `supplier-section__title`
   - `supplier-dialog__footer`
4. 折叠区优先使用简单布尔状态控制，不引入复杂组件依赖。

## 风险与注意事项

- 弹窗变宽后，需要确认在当前桌面分辨率下不会遮挡过度。
- 双列布局需要处理较窄窗口下的自动降级，避免字段挤压。
- 固定底栏与弹窗内部滚动要注意 `el-dialog` 内容区高度控制，避免 footer 抖动。
- 编辑场景与新增场景共用一个模板时，要确保文案和焦点处理不冲突。

## 验收标准

满足以下条件则视为本轮设计落地正确：

1. 新增供应商弹窗首屏能看到完整的关键录入区，不再是单列长表单。
2. 用户能清晰区分“基础识别”“联系人与沟通”“业务归属”“可选财务信息”。
3. 低频字段默认不打断首次建档。
4. 保存操作始终可见，不需要滚动到底部才可点击。
5. 现有保存接口、字段映射、编辑行为不回归。
